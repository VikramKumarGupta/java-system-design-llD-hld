## 🧠 When to Use Which Pattern

| Pattern | Typical interview clues | Example questions |
|---|---|---|
| HashMap / Frequency Map | Counting, duplicates, fast lookup | Two Sum, Valid Anagram, Top K Frequent |
| Two Pointers | Sorted arrays, pairs, in-place operations | Two Sum II, Container With Most Water |
| Sliding Window | Contiguous substring/subarray, longest/shortest window | Longest Substring Without Repeating Characters |
| Binary Search / BST | Sorted or ordered search space | Search in Rotated Sorted Array, Validate BST |
| DFS / BFS | Tree/graph traversal, reachability, shortest unweighted path | Number of Islands, Binary Tree Level Order |
| Stack / Monotonic Stack | Nested structures, next greater/smaller | Valid Parentheses, Daily Temperatures |
| Queue / Monotonic Queue | FIFO, level-order processing, window maximum | Sliding Window Maximum |
| Heap / PriorityQueue | Top-K, repeated min/max selection | Kth Largest Element, Merge K Lists |
| Greedy | Locally optimal decisions with a provable strategy | Jump Game, Non-overlapping Intervals |
| Dynamic Programming | Overlapping subproblems, optimal substructure | Coin Change, House Robber |
| Divide and Conquer | Split, solve recursively, combine | Merge Sort, Quick Sort, Maximum Subarray |

> **Interview tip:** First identify the input structure and constraints, then choose a pattern, explain the approach, analyze complexity, and only then write Java code.

## 🗺️ Suggested Interview Preparation Roadmap

1. **Foundation:** Arrays → Strings → HashMap → Two Pointers → Sliding Window.
2. **Core data structures:** Linked Lists → Stack → Queue → Heap.
3. **Trees and graphs:** Binary Trees → BST → DFS → BFS.
4. **Algorithm design:** Divide and Conquer → Greedy → Dynamic Programming.
5. **Backend interviews:** Java 8 → Hibernate/JPA → Spring Boot → LLD/HLD.

For each topic: **understand the pattern → dry-run an example → code without notes → test edge cases → explain time and space complexity**.

## ▶️ How to Use the Java Templates

1. Open a Java template from the table above.
2. Read the problem-solving approach and adapt the methods to a particular interview problem.
3. Run the relevant class in your Java IDE or copy the method into a scratch Java class.
4. Validate normal cases, boundary cases, duplicates, empty inputs, and large inputs.
5. Practice rewriting the logic from memory.

**Note:** These files are learning templates, not necessarily one directly runnable Maven/Gradle application. Some templates may need class-name, file-name, or method adjustments before compiling independently.
